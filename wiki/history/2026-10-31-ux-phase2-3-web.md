# 2026-10-31: UX audit Phases 2 and 3, rendering and phone flows

The web parts of Phase 2 (rendering) and Phase 3 (phone flows) of [[roadmap]]. The shelf
placement and the entity skeletons shipped in the wanted-shelf initiative; the server's
Phase 1 in its own.

## What changed

- **Rendering**: `content-visibility: auto` with intrinsic sizes on every `Row` section, every
  `SceneCard` and every category tile; Categories renders 72 tiles at a time on a sentinel
  (was 1,106 at once); "Pick up a station" holds its height while it loads (CLS source on
  Home); the player's time state stays as it was (F11 deferred, see Snags).
- **Cards on touch**: one 44 px "⋯" per card opens the same sheet as a long press; the sheet
  gained "Save to playlist…" (a `PlaylistSheet`) and lost "Station from here" (decision 5)
  and, on phones, "Delete…". The playlist menu itself is a sheet on touch.
- **Filter bar on phones**: one sideways-scrolling row (Filters, sort, Reshuffle, the count)
  and a "More" chip opening a sheet with Select, Select all, Pin to home and Station; the
  count row is desktop-only.
- **Scene page**: Delete moved from the action row into the details card beside Identify.
- **Player**: the gear menu is a bottom sheet on touch outside fullscreen.
- **Header**: turning Discreet or Private on shows a one-line toast saying what it does.
- **Playlists**: on phones the rows drop Move up/down and use a 96 px thumbnail.
- `components/Sheet.tsx` is the shared bottom-sheet / centred-panel.

## How it was verified

`node scripts/check.mjs` clean (one React Compiler warning fixed by declaring `setIdle`).
`mobile-check` on `/browse`, `/scene/2775`, `/tags`, `/playlists`: no overflow.
`phone-flow`: tapping "More" opened the list sheet (Select · Pin to home · Station); tapping
a card's "⋯" opened its sheet (Play, Add to Favorites, Save to playlist…, Mark as watched, Not
interested; no Delete); "Save to playlist…" opened the playlist sheet with Favorites (7) and
the New playlist field. Screenshots read.

## Snags

- `phone-flow`'s `tapText` matched hidden elements too: "Save to playlist" first hit the
  card's hidden icon (0×0) and the tap closed the sheet. Fixed the same day: `tapText` now
  skips elements with no box.
- The check scripts' blocked pattern `*/api/scenes/*/play` also blocks
  `/api/scenes/:id/playlists` (a GET), so playlist membership never loads headless. Harmless
  for checks; noted for anyone reading "blocked:" lines.
- F11 (the Player re-rendering 4×/s on `timeupdate`) shipped in a follow-up commit the same
  day: `createClock()` in `lib/playback.ts`, with the SeekBar, a `TimeReadout` and an `<At>`
  render-prop subscribing; the station page uses it too. Verified headless: the readout
  ticked 0:05 → 0:08 and the played span widened while the rest of the page did not render.
- Not done from Phase 3: Watched/Rating/Quality above the tag cloud in the Filters dialog;
  a "2 filters" chip on Browse for the tab badge; History remove already confirms, no Undo.

## Follow-ups the same day

- Filters dialog: the quick choices above Find and the tag cloud.
- Select mode: Shift+click range from the last card clicked, Cmd/Ctrl+A for everything
  loaded; Shift+right-click keeps the browser's menu. Verified with `desktop-check`, which
  gained `shift:true` on clicks and `cmd:true`/`ctrl:true` on keys: 2 selected after a
  Shift+click on the second card, 40 selected after Cmd+A, no flix menu on Shift+right-click.
- `prefers-reduced-motion`: a global rule in `index.css`, no hover previews.
